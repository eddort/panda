Дата: 2026-09-30. Изменение структуры и загрузки профилей; алгоритмы времени, консенсуса и native
клиентов не менялись. Новая перемотка без пропуска обязанностей остаётся отдельной задачей.

## TDD

До изменений: `deno task check` прошёл; `deno task test` — 19 passed, 0 failed, 10 opt-in ignored.

`deno test -A tests/bake_layout_test.ts tests/profiles_test.ts` после добавления регрессий и до
переноса: **6 failed, 5 passed**. Причины падений — старые пути, смешение recipes с тегами,
необнаруженный конфликт манифестов и невозможность восстановить legacy source по новому пути. Это
assert failures на поведении, не ошибка компиляции или недоступность Docker.

После переноса тот же набор вместе с проверкой изоляции: **12 passed, 0 failed**. Дополнительный RED
обнаружил, что перестановка сценариев между теми же файлами не меняет suite fingerprint. Карта
сценарий → файл добавлена в fingerprint; та же регрессия прошла.

Исходные логи этой сессии: `.cache/bake-layout/red.log`, `red-routing.log`, `green-initial.log`,
`unit-green.log` и `docker-baker.log`. Каталог `.cache/` не входит в Git.

## Неизменность артефактов

Перед перемещением сохранены SHA-256 исходных файлов. После переноса совпали все **15** проверяемых
файлов: 9 готовых манифестов, 2 патча и 4 Rust-исходника/теста. Изменений image IDs, bake keys, pins
и содержимого патчей нет. Клиенты не пересобирались.

Проверены и сохранены точные архивы native-входов всех 9 тегов. Для `pectra/geth-source` архив
отсутствовал и был создан до перемещения. Unit-регрессия дополнительно восстанавливает legacy hash
key из перенесённого файла без Git checkout и отклоняет отличающиеся байты.

CLI `bakes` перечисляет ровно 9 существующих артефактов; recipes не попадают в список. В тестовом
каталоге отдельно проверены теги `recipe` и `shared`, legacy-only манифест, одинаковые копии и отказ
при конфликте. Старые и новые пути не создают неоднозначности успешного чтения.

## Проверки

| Команда                                                  | Результат                              |
| -------------------------------------------------------- | -------------------------------------- |
| `deno task check`                                        | passed после переноса                  |
| `deno task test`                                         | 24 passed, 0 failed, 10 opt-in ignored |
| `deno task test:baker`                                   | 3 passed, 0 failed, 44 с               |
| `deno task test:profile gloas --bake stable`             | 8 passed, 0 failed, 566,9 с            |
| `deno task test:profile pectra --bake default`           | 6 passed, 1 failed (warp), 632,7 с     |
| `ZAP_PROFILE=pectra ZAP_BAKE=default deno task e2e:warp` | failed: второй скачок 20,679 с > 20 с  |

Docker-проверки подтвердили импорт и переиспользование артефактов между тегами, сохранение прежнего
тега при неудачной замене, восстановление того же локального image ID из архива и rollback без
удаления чужого ресурса. Синтаксис обоих перемещённых Python maintainer helpers проверен через AST.

Оба профиля затронуты переносом общего каталога тестов и загрузчика. Их интеграция проверена
последовательно отдельными командами на прежних образах. Это не меняет правило: редактирование
одного независимого профиля не запускает сборку/тесты другого. Исторические `verified` не
переносятся на новый suite fingerprint без реального прогона.

[Gloas verification](../reports/profiles/gloas/stable/verification.json) связывает все 8 отчётов с
run ID `1a37152e-768e-4ae9-a748-4afca8b3f2ae` и прежним bake key. Два скачка по 8192 слота вместе со
следующей транзакцией заняли 11,488 / 9,975 с. Деплой: 20 зависимых контрактов через raw RPC и
ethers, каждый в следующем блоке, без ручного продвижения времени.

[Pectra verification](../reports/profiles/pectra/default/verification.json), run ID
`3280f20f-4dd3-42d0-82cd-6138671fceea`, остаётся failed. Успешны baseline, lifecycle,
time/automine/finality/indexer, deposit/activation/consolidation, voluntary exit/full withdrawal и
20 последовательных деплоев. Общий исходный отчёт переноса: [JSON](../reports/bake-layout.json).

Первый полный прогон Pectra обнаружил сбой существующего warp-сценария. Первый скачок со следующей
транзакцией занял **22,243 с** при неизменном пороге 20 с. После восстановления финализации экспорт
истории подписей завершился Docker HTTP 409: VC был paused при запуске `exec`. Docker-события
содержат два близких цикла pause/unpause; источник второго не установлен. Тестовый стенд
`warp-892dfa07` удалён штатным cleanup, сохранены его `.zap/` логи и диагностика в
`.cache/bake-layout/pectra-warp-*`. Сам warp-сценарий совпадает с HEAD побайтно после нормализации
путей импортов. Это не подтверждает причину сбоя; Pectra нельзя объявлять полностью проверенным по
успешным соседним сценариям.

Отдельный повтор `e2e:warp` на том же коде завершился за 160,738 с: два скачка с последующей
транзакцией **17,195 / 20,679 с**, финализация восстановилась после обоих, все 64 валидатора
active/unslashed, проверки истории подписей прошли. Docker 409 не повторился. Итог сценария всё
равно **failed** из-за второго скачка сверх 20 с. Причина первого Docker-сбоя не установлена;
нестабильность SLA Pectra подтверждена повтором. Это открытые результаты проверки прежнего warp, не
исправленные переносом каталогов. Порог не ослаблялся, алгоритмы не менялись.

Этот повтор имеет отдельный run ID `bake-layout-warp-recheck` в
[warp.json](../reports/profiles/pectra/default/warp.json). Он не подменяет failed verification
полного набора. Финальный `bakes` подтвердил 9 артефактов: Gloas stable verified, Pectra default
unverified. После всех прогонов контейнеров с меткой `io.zap-net.id` не осталось; форматирование,
lint, типы и проверки whitespace рабочего дерева и staging прошли.

Полный native build/`test:clock` повторно не выполняется: байты native-входов не менялись;
архивирование/загрузка проверены отдельно. Этот отчёт не подтверждает будущие критерии честного warp
из `warp-tdd-acceptance.md`: нынешний большой скачок по-прежнему пропускает голоса.
