# Журнал экспериментов с перемоткой

2026-09-30. Историческая цель исследовательского цикла: **8192 слота вместе с первой следующей
транзакцией за ≤60 секунд**, без крупного переписывания клиента и без штрафов от пропущенных
обязанностей. 25 секунд остаётся желаемым результатом. Минуты не были разрешены пользователем:
прежняя трактовка ассистента была ошибочной.

Последнее ограничение: дальнейший поиск — **только алгоритмы**, без подбора потоков или scheduling.
Старые результаты сохраняются; новые сравнения используют фиксированную среду.

**Последующее решение пользователя:** закончить поиск ускорений, сохранить `direct-sync` и дать два
режима на одном bake: быстрый с реальными penalties и медленный честный. Прототипы групповых
подписей/MSM/shared-H остаются только в архиве. Все восемь native inputs совпали с Gloas
`direct-sync` (`e41c863b…`), поэтому откат или новая сборка клиента не потребовались.
[Двухрежимный контракт и новая проверка](warp-modes.md).

Это индекс проведённых опытов и отклонённых вариантов. Подробные команды, ключи сборок и RED/GREEN
сохранены в [фактических результатах](warp-tdd-results.md). Теоретические предложения не считаются
измеренными ускорениями. Полная [приёмка](warp-tdd-acceptance.md) ещё не пройдена.

## Короткие криптографические probes

Новый изолированный BLS baseline (тот же pinned Rust/blst, ARM64, 2 CPU): 11 проверок корректности
прошли; 64 подписи одного сообщения — **15,592 мс** при пустом success cache и **15,065 мс** при
заполненном cache с другими roots. Заранее выделенный компонентный бюджет ≤2 мс не выполнен:
сохранён performance RED, exit 2. RNG, subgroup checks, serialization и заполнение cache включены.
Это не сетевой benchmark. [Сырые данные](../reports/warp-tdd/same-message/baseline.json),
[тесты](../reports/warp-tdd/same-message/baseline-correctness.txt).

После сохранения baseline выполнен same-message MSM candidate: **14 тестов PASS**; mean
**3,329/4,229 мс**, p95 **3,433/7,660 мс**. Компонент ускорился в 3,6–4,7 раза, но ≤2 мс не
достигнуты: performance RED сохраняется. Клиент не менялся, полный warp не запускался.
[Результат](../reports/warp-tdd/same-message/candidate.json),
[проверки](../reports/warp-tdd/same-message/candidate-correctness.txt).

Shared-H signing probe: ordinary baseline — 4 теста PASS, кандидат — 7 PASS. Создание 64 подписей
при меняющихся roots: один worker **20,234 → 10,731 мс**, два workers **14,081 → 5,508 мс**.
Кандидат вычисляет публичную hash-точку один раз на batch, сохраняя все индивидуальные подписи. Gate
≤1 мс остаётся RED; сравнение содержит восемь samples, pool — модель scheduling VC.
[Данные, ограничения и обе версии исходников](../reports/warp-tdd/shared-hash/README.md).

Group-sync baseline: **9 тестов PASS**, mean **26,020 мс**, p95 **26,244 мс**, cold preparation
**0,271 мс**. Измерены live lookup, 64 подписи, их настоящая проверка и сборка четырёх aggregates;
дополнительные oracle checks исключены. В тестах уже воспроизведён zero-subnet при валидном полном
SyncAggregate. Gate mean ≤3 мс — RED, сохранён до реализации кандидата.
[Baseline](../reports/warp-tdd/group-sync/baseline.json),
[проверки](../reports/warp-tdd/group-sync/baseline-correctness.txt).

После baseline исполнен ephemeral group candidate: **12 тестов PASS**, mean **2,331 мс**, p95
**2,458 мс**, cold preparation **0,307 мс**. Временные scalar sums очищаются на каждом пути;
результаты побайтно совпадают с обычными подписями. Требуемая randomized verification четырёх
результатов включена. Компонентный gate ≤3 мс **GREEN**. Первый build error E0509 в test fixture
сохранён отдельно и не считается RED; исправление не меняло алгоритм.

Следующий парный опыт с одним full aggregate на 512 positions: baseline **27,816 мс** / p95 **31,219
мс** → candidate **1,563 мс** / p95 **1,612 мс**. Cold preparation кандидата **0,266 мс**. Оба
запуска прошли 12 library + 2 CLI теста. Baseline исполнен до включения candidate CLI;
криптографический helper и среда не менялись. Gate ≤3 мс **GREEN**. Это около 17,8× на данном
компоненте, а не на всей сети.
[Все исходники, raw evidence, границы проверки и воспроизведение](../reports/warp-tdd/group-sync/README.md).

Production integration, pool/restart safety, весь слот и 8192 + tx ещё не измерены. Все component
GREEN относятся к standalone probe, а не к готовому bake. Сохранён также
[алгоритмический проект и найденные риски](warp-group-sync-research.md).

## Итог алгоритмических peer reviews

[Остаточный бюджет](warp-algorithm-budget.md) не подтверждает, что component GREEN уже помещает всю
сеть в минуту. [PTC и lifecycle](warp-group-sync-research.md) допускают свёртку повторных публичных
точек по кратностям, но её native выигрыш не измерен.
[Attestation path](warp-attestation-research.md) уже умеет inclusion без wrappers; их controlled
удаление требует строгого FC/full-coverage gate. Это исходные проекты следующих TDD-проверок, а не
дополнительные исполненные ускорения. Клиент не менялся, большой прогон в этом исследовательском
цикле не повторялся.

## Архивное правило исследовательского цикла

Сначала определить конкретный источник нужного выигрыша и failing regression, затем минимальный
изолированный probe, после него 32/256 слотов со всеми проверками. Для 60 с средний полный бюджет —
7,324 мс/slot минус первая tx. Заведомо медленный кандидат не запускать на 8192 слотов. Не
переносить криптографию, историю, DB или первую tx за пределы измерения. Ранее добавленный
30-минутный watchdog в `warp.ts` был ошибочен для этой цели. После решения о двух режимах заменён
раздельными бюджетами; прежняя цель honest ≤60 с отменена. Новые эксперименты не запланированы.
